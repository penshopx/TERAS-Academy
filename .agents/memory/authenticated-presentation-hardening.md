---
name: Authenticated presentation hardening
description: Product rule for improving authenticated TERAS views without changing verified domain behavior.
---

Authenticated TERAS pages must present one canonical learner state through role-specific perspectives. Readiness, Safety, Evidence, Assessment, and Capability Passport must never imply conflicting learner conditions.

**Why:** The authenticated visual review found that individual dashboards showed valid fragments of the same state without enough connecting context, which could make a blocked learner appear unblocked or qualified.

**How to apply:** Improve responsive presentation, hierarchy, traceability, ownership, and decision context only. Do not change database schema, authorization, business rules, assessment or safety engines, readiness formula, Path A/B isolation, audit history, or stored-decision enforcement.

The completed landing, cross-role consistency, assessor decision support, safety-override prevention, and longitudinal Passport work form the current product baseline. Treat these foundations as frozen unless a verified regression requires repair.

**Why:** Reopening completed foundation or marketing work would mix product-engine hardening with presentation polish and create avoidable regression risk.

**How to apply:** Prioritize narrowly scoped hardening in this order: accessibility, consistency, then regression protection. Do not add large features or revisit the landing page while the remaining hardening queue is being completed.
