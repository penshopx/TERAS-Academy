# PHASE 0 — HARUS DIDAHULUKAN

Ini **bukan redesign**.

Ini hardening.

### 0.1 Normalisasi terminology

Kita harus menghapus seluruh istilah yang memberikan kesan TERAS:

* menerbitkan sertifikasi,
* membuat keputusan kompetensi resmi,
* memberikan otorisasi kerja,
* menjamin kompetensi lapangan.

Terminologi final:

| Jangan gunakan             | Gunakan                           |
| -------------------------- | --------------------------------- |
| Sertifikasi TERAS          | Program Pengembangan TERAS        |
| Competent                  | Ready for Next Stage              |
| Not Competent              | Needs Reinforcement               |
| Official Decision          | Internal Readiness Recommendation |
| Official Assessment Record | Internal Evaluation Record        |
| Official Capability Record | Longitudinal Capability Record    |
| Kesiapan Rilis             | Kesiapan Tahap Berikutnya         |
| Safety Cleared             | Safety Cleared for TERAS Practice |

**Catatan penting:** istilah teknis domain yang memang merepresentasikan keputusan lembaga eksternal tetap dapat ditampilkan sebagai **referensi/hasil proses eksternal**, tetapi TERAS tidak boleh mengklaim sebagai pihak yang menerbitkannya.

# PHASE 5 — REMEDIATION ENFORCEMENT

```text
REMEDIATION

Required Activities

✓ Scenario
✓ Practice
○ Evidence
○ Review
○ Reassessment
```

> **Remediation status = IN_PROGRESS**

bukan Complete.

**UI tidak boleh menentukan state secara bebas.**

## Jadi, sebelum coding berikutnya, baseline kita sekarang adalah:

> **TERAS Academy = Capability Development Platform**
>
> **LMS = Core Learning Engine**
>
> **Learning = Learn → Practice → Prove → Improve → Reassess**
>
> **Readiness = internal development/readiness recommendation, bukan sertifikasi resmi**
>
> **Capability Passport = longitudinal record**
>
> **Safety = non-compensatory hard gate**
>
> **AI = learning assistant, bukan assessor**
>
> **Existing foundation = dipertahankan dan dikembangkan secara additive, bukan dibangun ulang.**

Menurut saya **ini sudah cukup matang untuk dijadikan kontrak implementasi Replit**.

Tahap berikutnya yang paling aman adalah membuat **Prompt Replit #01 — Positioning Compliance + LMS Domain Contract Audit**, dengan instruksi kepada Replit untuk **memeriksa kode/schema aktual terlebih dahulu, membuat impact map, tidak langsung mengubah kode, lalu memberikan rencana perubahan yang dapat diverifikasi**. Ini mencegah Replit “mengarang” struktur baru di atas struktur TERAS yang sudah ada.
