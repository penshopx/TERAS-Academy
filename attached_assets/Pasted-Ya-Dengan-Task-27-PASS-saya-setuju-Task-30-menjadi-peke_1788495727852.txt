# 1. TUJUAN UTAMA

Bangun **Learner Orientation Layer** pada LMS TERAS Academy.

Tujuannya bukan membuat dashboard LMS besar.

Tujuannya adalah memastikan setiap learner yang masuk ke LMS selalu dapat memahami dengan cepat:

1. Saya sedang mengikuti program/pathway apa?
2. Saya sedang belajar course apa?
3. Saya berada di module mana?
4. Saya berada di lesson mana?
5. Aktivitas apa yang sedang/harus saya kerjakan?
6. Apa yang sudah selesai?
7. Apa tindakan berikutnya yang valid?
8. Mengapa tindakan tersebut menjadi next action?

Prinsip utama:

> **The LMS must always answer: “Where am I, what have I completed, and what should I do next?”**

# 6. CONTINUE LEARNING

`Continue Learning` harus menjadi primary CTA.

Sistem harus menentukan tujuan berdasarkan **server-side learning state dan persisted progress**.

Jangan menentukan next destination hanya berdasarkan:

* array index frontend;
* localStorage;
* browser state;
* hardcoded lesson ID;
* hardcoded activity ID.

Prioritas:

```text
Persisted Learning State
        ↓
Current Activity
        ↓
Next Valid Action
        ↓
Continue Learning
```

Jika learner sedang berada pada activity `IN_PROGRESS`, Continue Learning harus mengembalikannya ke activity tersebut.

Jika activity telah selesai dan activity berikutnya tersedia, Continue Learning diarahkan ke activity berikutnya yang valid.

Jika lesson selesai tetapi outcome verification masih diperlukan, UI harus menunjukkan status tersebut dan tidak mengklaim achievement.

# 7. NEXT ACTION ENGINE — UX LAYER

Jangan membuat readiness engine baru.

Jangan membuat competing state engine.

Gunakan state dan transition authority yang sudah ada.

Buat hanya **read-only next-action resolver/presentation layer** bila diperlukan.

Contoh:

```text
CURRENT STATE
IN_PROGRESS

NEXT ACTION
Continue Activity
```

atau:

```text

Await Outcome Verification
```

atau:

```text

NEXT ACTION
Practice Required
```

Jika transition belum valid, UI tidak boleh menawarkan tombol yang menyebabkan invalid transition.

# 17. IDENTITY

Gunakan identity architecture Task #27.

Jangan menerima learner ID dari frontend sebagai authority.

Semua learner-specific data harus berasal dari authenticated server-side identity.

Pastikan:

```text

    ↓

Learner B
    ↓
Current Learning B
```

Tidak boleh terjadi cross-learner leakage.

# 18. PATHWAY ISOLATION

Pastikan Current Learning dan Continue Learning selalu pathway-scoped.

Jika learner berpindah:

```text

```

Lakukan regression test khusus untuk:

* current course;
* current lesson;
* current activity;
* progress;
* continue learning.

# 22. API

Reuse existing API terlebih dahulu.

Jika endpoint baru benar-benar diperlukan, dokumentasikan alasan dan buat melalui OpenAPI contract.

Jangan:

* membuat endpoint duplicate;
* membaca database langsung dari frontend;
* menambahkan learner ID sebagai trust boundary;
* membuat endpoint yang bypass transition service.

Jika diperlukan, pertimbangkan read-only endpoint seperti:

```text
GET /api/learning/current
```

atau equivalent existing route.

Tetapi hanya buat jika functionality tersebut belum tersedia.
