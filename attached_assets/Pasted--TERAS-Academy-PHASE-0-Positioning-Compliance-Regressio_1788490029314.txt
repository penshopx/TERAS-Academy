# TERAS Academy — PHASE 0

## Positioning Compliance + Regression Guard

### IMPLEMENTATION TASK — CONTROLLED HARDENING

Audit dan implementation blueprint sebelumnya sudah selesai.

Status audit:

```text
AUDIT: PASS
PHASE 1: BLOCKED
PHASE 0: READY
```

Sekarang implementasikan **PHASE 0 ONLY**.

Tujuan Phase 0:

1. Menghilangkan positioning yang dapat membuat TERAS terlihat sebagai lembaga sertifikasi/assessor resmi.
2. Mengunci terminology internal TERAS.
3. Membuat regression guard untuk mencegah terminology tersebut kembali.
4. Memperkuat regression tests untuk prinsip:

   * Completed ≠ Capable ≠ Ready
   * Safety is non-compensatory
   * Path A/B isolation
   * Authorization boundary
5. Menghilangkan shortcut remediation yang dapat membuat proses terlihat selesai tanpa bukti proses yang sebenarnya.

**JANGAN mengimplementasikan LMS Foundation pada fase ini.**

---

# 1. CORE POSITIONING

TERAS Academy harus selalu diposisikan sebagai:

> **Capability Development Platform**

dengan:

> **LMS sebagai Core Learning Engine**

TERAS membantu proses:

```text
Learn
→ Practice
→ Evidence
→ Feedback
→ Improve
→ Reassess
→ Readiness
→ Capability Passport
```

TERAS bukan:

* lembaga sertifikasi;
* assessor resmi;
* pengganti proses uji kompetensi resmi;
* penerbit sertifikat kompetensi;
* pemberi keputusan kompetensi resmi.

Semua readiness yang dihasilkan TERAS adalah:

> **Internal Readiness Recommendation**

dan bukan keputusan kompetensi resmi.

# 2. SAFE TERMINOLOGY CONTRACT

Gunakan terminology berikut sebagai canonical vocabulary.

| Jangan gunakan sebagai terminology TERAS | Gunakan                                            |
| ---------------------------------------- | -------------------------------------------------- |
| Sertifikasi TERAS Academy                | Program Pengembangan TERAS Academy                 |
| Competent                                | Ready for Next Stage                               |
| Not Competent                            | Needs Reinforcement                                |
| Official Decision                        | Internal Readiness Recommendation                  |
| Official Assessment                      | Internal Evaluation                                |
| Official Assessment Record               | Internal Evaluation Record                         |
| Official Attempt                         | Internal Evaluation Attempt                        |
| Official Attempt History                 | Internal Evaluation History                        |
| Official Capability Record               | Longitudinal Capability Record                     |
| VERIFIED ENGINE RECORD                   | INTERNAL TERAS CAPABILITY RECORD                   |
| Kesiapan Rilis                           | Kesiapan Tahap Berikutnya                          |
| Certification Decision                   | Readiness Recommendation                           |
| Assessor Decision                        | Evaluator Recommendation / Internal Recommendation |

### Catatan penting

Jangan melakukan global blind replacement.

Setiap perubahan harus diperiksa berdasarkan konteks.

Contoh:

Jika `Competent` merupakan terminology teknis yang memang diperlukan untuk kompatibilitas data lama atau integrasi eksternal, pertahankan sebagai **legacy/internal compatibility value** bila benar-benar diperlukan, tetapi jangan tampilkan sebagai keputusan resmi TERAS kepada pengguna.

Jika enum/API legacy harus dipertahankan demi backward compatibility:

```text
legacy value
↓
internal mapping
↓
canonical TERAS terminology
```

Jangan merusak data lama hanya demi mengganti string.

# 4. POSITIONING REGRESSION GUARD

Tambahkan automated regression protection.

Tujuannya adalah mencegah developer berikutnya secara tidak sengaja mengembalikan terminology yang salah.

Regression guard minimal harus mendeteksi user-facing atau canonical domain usage yang kembali menggunakan:

```text
Official Decision
Official Assessment
Official Capability Record
Certification
Sertifikasi
Competent
Not Competent
Kesiapan Rilis
```

Namun guard **tidak boleh sekadar melakukan string grep buta** jika string tersebut berada dalam:

* migration history;
* legacy compatibility mapping;
* historical data;
* comments yang menjelaskan terminology lama;
* test yang secara eksplisit menguji backward compatibility.

Guard harus fokus pada:

```text
canonical domain vocabulary
+
user-facing UI
+
active API contracts
```

Dokumentasikan exception secara eksplisit.

# 5. COMPLETED ≠ CAPABLE ≠ READY

Tambahkan regression tests yang membuktikan ketiga konsep tidak dapat saling menggantikan.

Minimal test scenarios:

### Scenario A

Learning activity selesai.

Expected:

```text
learning completion = true
capability = not automatically proven
readiness = not automatically proven
```

### Scenario B

Practice selesai.

Expected:

```text
practice = completed
capability = requires evidence/review according to contract
readiness = not automatically proven
```

### Scenario C

Evidence diterima.

Expected:

```text
evidence = accepted
readiness = still subject to all readiness prerequisites
```

### Scenario D

Average score tinggi tetapi critical safety failure terjadi.

Expected:

```text
readiness = blocked
```

### Scenario E

Assessment/review pass tanpa required learning/practice/evidence chain.

Expected:

```text
cannot bypass required prerequisites
```

# 6. SAFETY REGRESSION GUARD

JANGAN mengubah:

```text
artifacts/api-server/src/lib/safety.ts
```

dan jangan mengubah readiness formula.

Tambahkan regression tests terhadap existing behavior.

Minimal:

```text
critical criterion = 0
→ BLOCKED

critical criterion = 1
→ BLOCKED

high average score
+
critical safety failure
→ BLOCKED

requested positive decision
+
critical safety failure
→ BLOCKED
```

Pastikan:

> Average score never overrides critical safety failure.

Jika existing tests sudah membuktikan hal tersebut, pertahankan dan tambahkan hanya coverage yang masih kurang.

# 7. REMEDIATION BYPASS — CRITICAL HARDENING

Audit endpoint:

```text
artifacts/api-server/src/routes/learner.ts
```

dan semua route/service yang dapat mengubah status remediation.

Temukan mekanisme seperti:

```text
Mark Plan Complete
```

atau equivalent behavior.

Masalah yang harus dihilangkan:

```text
Remediation Plan
→ manually mark complete
→ readiness becomes eligible
```

jika required activities sebenarnya belum dilakukan.

Target:

```text
Remediation
↓
Required Activity
↓
Completion
↓
Re-practice
↓
New Evidence
↓
Review
↓
Reassessment
```

Pada Phase 0, lakukan **minimal safe hardening**:

Jika remediation memiliki required activities yang belum terpenuhi:

```text
Mark Complete
→ REJECT
```

Jangan membuat shortcut.

Return error yang jelas dan aman.

Contoh semantik:

```text
REMEDIATION_PREREQUISITES_NOT_MET
```

Jangan menganggap seluruh remediation selesai hanya karena operator/evaluator meminta completion.

# 10. PATH A / PATH B REGRESSION

Jangan mengubah mekanisme Path A/B.

Tambahkan atau pertahankan tests untuk memastikan:

```text
Path A evidence
≠
Path B evidence
```

dan:

```text
Path A readiness
≠
Path B readiness
```

Cross-path evidence tidak boleh memenuhi requirement.

Cross-path mutation tidak boleh berhasil.

Concurrent pathway switching tidak boleh menghasilkan record yang salah pathway.

# 16. DATABASE SAFETY

Phase 0:

**DO NOT DELETE DATA.**

**DO NOT RESET DATABASE.**

**DO NOT DROP TABLE.**

**DO NOT rename existing tables unless absolutely required and explicitly justified.**

**DO NOT rewrite historical event records.**

Jika schema change benar-benar diperlukan:

1. jelaskan alasannya;
2. buat additive migration;
3. jangan destructive migration;
4. pastikan existing tests tetap pass.

Jika tidak diperlukan, jangan lakukan schema change.

# 19. ACCEPTANCE CRITERIA

Phase 0 dianggap PASS apabila:

### Positioning

* [ ] Tidak ada active user-facing official certification claim.
* [ ] Passport menggunakan Longitudinal Capability Record.
* [ ] Assessment menggunakan Internal Evaluation terminology.
* [ ] Readiness menggunakan Internal Readiness Recommendation.
* [ ] Landing page tidak menyatakan TERAS sebagai certification authority.

### Safety

* [ ] Critical safety failure tetap non-compensatory.
* [ ] Tidak ada perubahan safety formula.

### State

* [ ] Completed tidak otomatis berarti Capable.
* [ ] Capable tidak otomatis berarti Ready.
* [ ] Readiness tidak dapat dicapai dengan shortcut.

### Remediation

* [ ] Incomplete remediation tidak dapat ditandai complete melalui shortcut.
* [ ] Required activity prerequisites tetap enforced.

### Authorization

* [ ] Unauthorized mutation rejected.
* [ ] Tidak terjadi mutation setelah rejection.

### Pathway

* [ ] Path A/B isolation tetap bekerja.
* [ ] Cross-path evidence tidak dapat memenuhi requirement.

### Passport

* [ ] Historical record tetap tersimpan.
* [ ] Tidak ada destructive rewrite.

### Regression

* [ ] Existing tests pass.
* [ ] New regression tests pass.
* [ ] Typecheck pass.
* [ ] Build pass.
