Lanjutkan dari kondisi terakhir.

---

## PRIORITY 1 — COMPLETE DATABASE RECONCILIATION

Temuan saat ini:

Application code menggunakan:

`teras_people.email`

tetapi database aktif sebelumnya belum memiliki kolom tersebut.

Post-merge setup juga sebelumnya menggunakan package filter yang salah sehingga migration tidak dijalankan.

Selesaikan akar masalah ini.

Pastikan:

* database schema sesuai dengan current Drizzle schema
* `teras_people.email` tersedia apabila memang diwajibkan oleh current application schema
* migration dapat dijalankan non-interactively
* unique constraint ditangani secara aman
* existing data tidak hilang
* migration tidak bersifat destructive tanpa alasan
* migration dapat dijalankan secara deterministik
* post-merge setup menggunakan package/workspace target yang benar

Jangan menggunakan workaround yang hanya membuat test lewat.

# PRIORITY 2 — MAKE POST-MERGE SETUP RELIABLE

Perbaiki mekanisme post-merge setup sehingga setiap merge dapat melakukan:

1. schema reconciliation / migration
2. seed
3. validation
4. smoke test

Pastikan tidak ada lagi ketergantungan terhadap interactive stdin.

Jika migration membutuhkan konfirmasi:

Jangan mengandalkan:

`yes`

atau stdin injection.

Lebih baik gunakan migration SQL eksplisit yang telah direview.

# PRIORITY 3 — REVIEW MIGRATION SAFETY

Sebelum menjalankan migration yang berkaitan dengan:

`teras_people.email`

pastikan:

* apakah existing records memiliki email null?
* apakah penambahan column harus nullable terlebih dahulu?
* apakah unique constraint aman diterapkan?
* apakah ada duplicate email?
* apakah existing data membutuhkan backfill?
* apakah application code mengharuskan email NOT NULL?

Jangan langsung membuat column `NOT NULL UNIQUE` jika existing data dapat menyebabkan migration gagal atau kehilangan data.

Pilih migration strategy yang paling aman terhadap data existing.

# PRIORITY 10 — AUTHORIZATION

Explicitly test backend authorization.

## Learner

Must NOT be able to:

* submit assessor decision
* approve evidence as assessor
* modify assessment result
* modify readiness result

## Trainer

May:

* review practice
* provide feedback
* review evidence according to assigned permissions

But must NOT automatically gain assessor authority.

## Assessor

May:

* perform assessment
* submit rubric
* make assessment decision

Authorization must be enforced server-side.

Hiding buttons in frontend is NOT sufficient.
