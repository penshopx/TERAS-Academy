# MASTER BUILD PROMPT — TERAS ACADEMY

## Web Application Development Specification v1.0

Anda adalah **Senior Product Architect, Full-Stack Engineer, UX/UI Designer, Database Architect, dan AI Application Engineer**.

Bangun aplikasi web bernama:

# TERAS Academy

### Evidence-Based Capability Development & Readiness Platform

Tagline:

**Learn. Practice. Prove. Improve. Ready.**

---

# 1. MANDATORY PRODUCT PRINCIPLE

TERAS Academy BUKAN LMS biasa.

Jangan membangun aplikasi sebagai sekadar:

* course marketplace
* video learning platform
* quiz platform
* certificate generator
* generic AI chatbot

TERAS Academy adalah:

> **Capability Development System yang menggunakan learning sebagai proses untuk membangun capability, practice sebagai jembatan, evidence sebagai bukti, assessment sebagai verifikasi, remediation sebagai perbaikan, dan readiness sebagai status kesiapan.**

Objek utama sistem adalah:

**CAPABILITY**

bukan:

**COURSE**

Struktur konseptual:

**Capability Domain**
→ **Program**
→ **Pathway**
→ **Capability**
→ **Learning Outcome**
→ **Module**
→ **Learning**
→ **Practice**
→ **Assessment**
→ **Evidence**
→ **Gap**
→ **Remediation**
→ **Reassessment**
→ **Readiness**
→ **Capability Passport**

---

# 2. MASTER LEARNING LOOP

Implementasikan core journey berikut:

**Diagnostic**
→ **Individual Learning Plan**
→ **Learning**
→ **Practice**
→ **Assessment**
→ **Evidence**
→ **Gap Analysis**
→ **Remediation**
→ **Re-practice**
→ **Re-assessment**
→ **Readiness**
→ **Capability Passport**

Ini adalah CORE ENGINE aplikasi.

Jangan menggantinya dengan alur LMS standar seperti:

Course → Lesson → Quiz → Certificate.

## PATH B — PRE-CERTIFICATION

## Engine 3 — Practice Engine

This is a major differentiator.

Practice must follow:

**Demonstrate**
→ **Guided Practice**
→ **Independent Practice**
→ **Feedback**
→ **Re-practice**

Practice is NOT simply a quiz.

Support:

* task
* assignment
* simulation
* practical task
* trainer-guided practice
* independent practice
* submission
* feedback

# 7. ASSESSMENT ENGINE

Implement three assessment layers.

### KNOWLEDGE

Question:

**"Apakah peserta tahu?"**

### APPLICATION

Question:

**"Apakah peserta mampu menerapkan?"**

### PERFORMANCE

Question:

**"Apakah peserta mampu melakukan?"**

Additionally implement:

### SAFETY GATE

Critical safety failure is:

**NON-COMPENSABLE**

A participant cannot be declared ready if they fail a critical safety requirement.

---

# 8. ASSESSMENT RUBRIC

Use:

### 0 — Not Demonstrated

Capability has not been demonstrated.

### 1 — Requires Substantial Assistance

Participant can perform only with significant assistance.

### 2 — Meets Expected Standard

Participant performs according to expected standard.

### 3 — Strong / Consistent Performance

Participant performs consistently and independently.

Every assessment result must be traceable to:

* criterion
* observation
* evidence
* assessor/trainer
* date
* result

---

# 9. EVIDENCE ENGINE

Evidence is a first-class object in the database.

Do NOT treat evidence as simple file attachments.

Each evidence record must have:

* Evidence ID
* Learner ID
* Program ID
* Capability ID
* Module ID
* Task ID
* Assessment ID
* evidence type
* date
* description
* reviewer
* validity
* relevance
* sufficiency
* traceability
* status
* reviewer comments

Evidence types:

* photo
* video
* document
* work output
* measurement record
* observation record
* project output
* practical output
* assessment record

Evidence status:

* Submitted
* Under Review
* Valid
* Needs Revision
* Rejected

Core rule:

> **No final capability achievement without adequate evidence.**

---

# 10. GAP ENGINE

Implement:

**Required Capability vs Demonstrated Capability**

The system should identify gaps at indicator/criteria level where possible.

Gap status:

* No Gap
* Minor Gap
* Moderate Gap
* Major Gap
* Critical Gap

Each gap should contain:

* gap ID
* learner
* capability
* criterion
* current status
* required status
* diagnosis
* recommended action
* priority
* status

---

# 11. REMEDIATION ENGINE

Do NOT simply tell the participant:

"Repeat the module."

Instead:

**Gap**
→ **Intervention**
→ **Practice**
→ **Evidence**
→ **Reassessment**

Remediation should be specific to the gap.

Examples:

* repeat theory section
* watch targeted video
* repeat practical task
* additional trainer coaching
* additional assignment
* additional evidence
* targeted simulation

---

# 12. REASSESSMENT ENGINE

Participants who do not meet the required standard can enter:

**Remediation → Re-practice → Reassessment**

Store:

* original result
* gap
* remediation
* new attempt
* new evidence
* new result
* assessor/trainer
* date
* final decision

Maintain complete attempt history.

Do NOT overwrite previous assessment results.

---

# 13. READINESS ENGINE

Readiness must NOT equal:

"course completed."

Calculate/readiness based on:

* knowledge
* application
* performance
* safety
* evidence
* assessment results
* unresolved gaps
* pathway requirements

Readiness status:

### NOT READY

Major requirements are not met.

### PARTIALLY READY

Some requirements are met but gaps remain.

### READY

Required conditions have been met.

Show:

* readiness score
* current gate
* next gate
* outstanding gaps
* missing evidence
* recommended next action

---

# 14. GATE SYSTEM

Implement:

### G1 — Knowledge Ready

### G2 — Safety Ready

### G3 — Practical Ready

### G4 — System Ready

### G5 — Verification Ready

### G6 — Pathway Ready

The dashboard should clearly show:

Current Gate → Next Gate → Requirements.

**ONE longitudinal record**

across multiple programs.

NOT_STARTED
→ IN_PROGRESS
→ SUBMITTED
→ REVIEWED

IDENTIFIED
→ PLANNED
→ IN_PROGRESS
→ COMPLETED
→ VERIFIED

NOT_READY
→ PARTIALLY_READY
→ READY

Use controlled state transitions rather than arbitrary text fields.

# 30. AI ARCHITECTURE

AI must be an intelligence layer.

Do NOT create only a generic chatbot.

Prepare separate AI services/modules:

### AI Learning Assistant

Helps learners understand content.

### AI Practice Coach

Helps learners prepare and improve practice.

### AI Evidence Assistant

Helps identify whether submitted evidence appears complete/relevant.

AI should NOT make final formal assessment decisions where human assessment is required.

### AI Gap Analyst

Analyzes:

Required Capability vs Demonstrated Capability.

### AI Remediation Planner

Generates targeted remediation recommendations.

### AI Readiness Advisor

Explains:

* why learner is not ready
* what gaps remain
* what evidence is missing
* what should be done next

### AI Trainer Assistant

Helps trainers analyze learner progress.

### AI Content Assistant

Helps content developers draft:

* learning objectives
* explanations
* practice tasks
* assessment questions
* remediation activities

All AI recommendations must remain reviewable by humans.

---

# 31. AI SAFETY / GOVERNANCE

AI must NOT:

* fabricate assessment evidence
* automatically certify competence
* override assessor decisions
* invent regulations
* claim official certification
* alter assessment records without authorization

AI outputs should be labeled as:

**AI Recommendation**

when appropriate.

Human decision remains authoritative for formal assessment and certification-related decisions.
